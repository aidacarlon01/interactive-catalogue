1. Reading content

Reading content

The components that carry most of a course: text, links, lists, tables, accordions, scenarios and code.

Most of a learner's time is spent reading, so most of the theme's work happens here. Body text is set in Roboto at 16px with generous line spacing, headings in Roboto Condensed, and every colour pair meets WCAG 2.2 AA contrast. These styles are scoped to the page body only, so Canvas's own menus and admin screens are never touched.

Headings and body text

Use a Heading 2 for each main section of a page. It's set in Monash Blue with a short accent rule beneath it, which gives learners a clear landmark as they scroll. Hierarchy comes from size and the rule, not from bold, which keeps the page calm.

A Heading 3 groups content inside a section

Use a Heading 3 when a section has two or more distinct parts. Don't skip levels: a Heading 3 always sits under a Heading 2, because screen reader users navigate a page by its heading outline.

Links

Inline links keep their underline, so colour is never the only thing that marks them as links. That's WCAG success criterion 1.4.1, Use of Color, and it's a deliberate step up from earlier builds that removed underlines. Write link text that makes sense out of context: name the destination, never "click here".

Lists

Use a bulleted list when order doesn't matter:

  • items that can be read in any order
  • short, parallel phrases that start the same way
  • three to seven items, so the list stays scannable.

Use a numbered list when it does:

  1. Write the steps in the order a learner carries them out.
  2. Start each step with a verb.
  3. Keep one action per step.

Tables

Use a table for content with rows and columns that a learner will compare. Give it a header row, and keep cells short.

Accordions

Accordions are native <details> and <summary> elements, so they're keyboard and screen reader accessible without any JavaScript. Select a heading to open it.

When should I use an accordion?

Use one for supporting detail that some learners will want and others won't, such as worked examples, technical requirements or extra reading. If every learner needs it, leave it on the page.

How many accordions can I use?

Group three to six in a set. A long run of closed accordions hides the shape of the page and makes learners open each one to find what they need.

This accordion has no disclosure triangle

Add the accordions--no-marker class to hide the triangle for a single accordion. The default keeps it, because the triangle tells learners the heading opens.

Scenario panel

The scenario panel, with its folded corner, sets a case apart from the teaching around it. Learners can spot it at a glance when a later page asks them to return to it.

Scenario: the new course build

A learning designer hands over storyboards for a six-module course. The learning technologist builds every page from this set of components, so each page looks and behaves the same, and the course passes its accessibility review without page-by-page fixes.

Use the panel for one scenario per page. Keep it to a few short paragraphs, and give it a bold first line so learners know which case it is.

Code

Inline code, such as the wcag-well-heading class, sits in a light chip in the body text. Longer code goes in a code block, which keeps its spacing and scrolls sideways rather than wrapping:

<h4 class="box_heading wcag-well-heading">Note</h4>
<div class="box_content wcag-well-content">
  <p>Use a note for the one thing a learner must not miss.</p>
</div>

Author code blocks as plain <pre> text. There's no syntax highlighting add-on, so the text stays high-contrast on the grey panel and is easy to build automatically.
