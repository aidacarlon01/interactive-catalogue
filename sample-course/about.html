About this build

About this build

A Canvas LMS theme for a university's AI Career Accelerator: one stylesheet, one script, and the decisions behind both.

I designed and coded this theme for an online Career Accelerator delivered in Canvas. It targets WCAG 2.2 AA, uses only the university's official co-branding palette, and binds to the same component classes the course content is authored with. Every decision is recorded in two companion documents, so a reviewer can see why each value was chosen and change it from a single point. This sample course runs the production files; only the course frame around them is recreated for the web.

Starting point

Two earlier builds were audited as references. One scoped its selectors to authored content, carried full accessibility scaffolding, and took its colours verbatim from the client's published brand site. The other themed itself off a logo colour, used global, unscoped selectors and had minimal accessibility support. I built on the first pattern and recorded what was rejected from the second, and why.

Standard

The theme targets WCAG 2.2 AA rather than 2.1. AA is the universal baseline for web services, and 2.2 is a superset that adds focus-appearance and target-size criteria a stylesheet directly controls, so it future-proofs the build at almost no cost.

Colour

The palette is the official one only: the brand blue, black, white and three greys. There are exactly two additions, both flagged: a secondary dark blue the university uses on the web, and a focus-ring colour for accessibility. Every other neutral is a tint of the official light grey faded over white, so each panel and border traces back to the palette. Every pair was checked against the WCAG contrast formula.

Typography

Headings are Roboto Condensed and body text is Roboto, with Arial as the brand's named fallback, matching the co-branding guide exactly. The minimum body size is 16px, text is left-aligned, and hierarchy comes from size and a brand-blue underline at regular weight rather than heavy bold.

Two deliberate departures from the brand guide

Sentence-case headings. The guide asks for uppercase titles. Content headings are full sentences, and forcing them to uppercase reads as shouting, hurts readability and can change screen reader pronunciation.

Rounded corners. The guide shows square buttons, but buttons, cards, wells and dialogs share one radius in the LMS. Squaring only the buttons would break that consistency. Both are one-line changes if a brand review requires them.

Accessibility decisions

  • Links keep their underline. Colour is never the only cue (SC 1.4.1). On hover and focus, the underline thickens and the colour deepens, with no change in weight, so nothing shifts on the page.
  • Quotes are upright, not italic. The guide limits italics to three to five words, and long italic runs are harder to read for dyslexic and low-vision readers.
  • A visible focus ring on every authored component, shown to keyboard users but not on mouse click, while Canvas's own interface keeps its native focus styling.
  • Every banner keeps a real heading. The original page title stays in the page for screen readers behind the decorative overlay.
  • Grids reflow to fewer columns on narrow screens (SC 1.4.10), and animations stop for learners who ask for reduced motion.

Structure

Styles are scoped to authored content, so Canvas's navigation, sidebars and admin screens are never restyled. The few rules that reach outside that scope, such as page width and the focus layer, are listed as intended exceptions. The content column is 1100px.

Two behaviours are contracts between the stylesheet and the script, and they're the first thing to re-check when either file changes:

  1. Transcripts degrade safely. The script adds a class to the page when it loads, and the stylesheet hides the inline transcript only when that class is present. If the script fails, the transcript stays on the page.
  2. Image zoom is opt-in. Only images an author marks as zoomable get the zoom cursor and become lightbox triggers, so the two files never disagree about which images are interactive.

Discussion pages are the one page type without a banner. Canvas's discussions interface renders its title after the theme script has run, so a banner could hide the title without being able to replace it. The title is styled in CSS instead, against a stable attribute that doesn't change between Canvas releases.

The script

The JavaScript is seven small, self-contained modules plus one shared helper. Each module is safe to run more than once, and a shared content watcher re-runs them whenever Canvas re-renders part of a page, so components added after the first load still work. Every module exists because a component in the content needs it.

Theme script modules
ModuleWhat it does
H5P resizerSizes H5P frames from their height messages, checking the sender's origin and clamping the height
Image lightboxTurns opted-in images into keyboard-operable zoom buttons that open a true modal dialog
Transcript modalOpens the transcript in a focus-managed dialog, and stops Canvas opening its own plain dialog
Card navigationMakes linked cards work with Enter and Space, without hijacking controls nested inside
Page bannerRebuilds the banner Canvas strips on save, and writes the page title into the overlay
Video label cleanupRemoves the stray "[Video]" text Canvas adds beside video embeds
Glossary modalTurns glossary terms into accessible buttons that open their definition in a dialog

All three dialogs move focus inside on open, keep the Tab key within them, close with Escape, and hand focus back to whatever opened them. While a dialog is open, the rest of the page is made inert.

Deliberately left out

Learning outcomes hidden in a pop-up

An earlier build hard-coded around 330 lines of course-specific outcomes inside the theme script. That ties content to presentation and hides outcomes behind a click. Outcomes are authored on the page instead.

Forcing links to open in new tabs

New windows break the back button and disorient assistive-technology users. Links open in the same tab unless an author chooses otherwise.

Loading the whole Google Fonts library

An earlier build imported hundreds of font families on every page. This theme loads only the two it uses.

A script for accordions

Accordions are native details and summary elements, which work with a keyboard and screen reader with no script at all. One less moving part.

How this sample differs from Canvas

The page bodies, stylesheet and script are the production files. Around them, a separate stylesheet recreates the Canvas frame: navigation, breadcrumb and Previous/Next buttons. Videos are placeholders because course videos belong to the client, well icons are inline SVG because the Canvas icon font isn't available, and the H5P resizer is swapped for one that sizes the embedded interactives.
